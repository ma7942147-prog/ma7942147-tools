# fireworks-cut — 煙火／活動影片精華剪輯

把一堆手機拍的煙火片段，自動挑出爆點、剪成一支帶字卡的精華片。
第一支作品：**《文聖堂 煙火》**（2026-11-07 週六，台南市南區灣裡黃金海岸）。

## 精彩片段怎麼挑的

不是憑印象亂抓時間點，是量出來的：

1. 每段影片降到 64×36 灰階、10fps 取樣
2. 算每一幀的平均亮度 —— **煙火爆開就是一個亮度尖峰**
3. 減掉該段第 20 百分位當基線（扣掉現場路燈、廟埕燈的底噪）
4. 取 0.8 秒窗內的極大值、彼此至少間隔 1.5 秒 → 爆點清單
5. 以爆點為中心前後留 2~3 秒組成鏡頭

```bash
python3 burst.py <影片...>      # 列出每段的爆點與每 5 秒的強度
```

## 剪輯與輸出

`edl.py` 是剪輯表（素材、進出點、速度、時刻標）與活動資訊；
`render.py` 讀它產生成品。

```bash
python3 render.py --src <素材夾> --out <輸出夾> --portrait --landscape
python3 render.py --src ... --out ... --portrait --relabel   # 只改字卡，沿用串接檔
```

串接好的 `joined_<比例>.mp4` 會留著。只改活動資訊或字卡樣式時加
`--relabel`，跳過整輪重剪，幾分鐘就好。

- **直式 1080×1920**：手機直拍的原生比例，滿版不裁切
- **橫式 1920×1080**（`--fill blur`，預設）：原片置中，兩側用自己的放大
  模糊版填滿。完整保留畫面，但實際內容只佔中間 32%
- **橫式 1920×1080**（`--fill crop`）：放大到滿版再裁成 16:9。畫面飽滿、
  沒有模糊邊，代價是切掉上下（廟簷與人群幾乎看不到）

裁切版的視窗高度不是固定置中，是量出來的：

```bash
python3 cropwin.py <素材夾>     # 算出每個鏡頭的 CROP_Y，貼回 edl.py
```

直式裁成 16:9 只留得下 31.6% 的高度，固定置中會切掉爆點。`cropwin.py`
算每一列**沿時間的標準差**，用 31.6% 高的滑動視窗找變異度總和最大處。
用標準差而不是平均亮度，是因為地面的發射火光與廟埕燈是持續亮著的，
比平均亮度會贏過空中短暫的爆開；持續亮的變異小，爆開的變異大。
即使如此，最下緣的發射尾焰與翻騰亮煙變異仍大，所以再排除底部 18%，
只在天空範圍裡找。

鏡頭之間影像用 xfade、聲音用 acrossfade，同步 0.45 秒交叉淡入，
現場的爆炸聲和人聲不會在剪點上硬切。

## 慢動作

120fps 拍的素材在 `edl.py` 裡把速度設成 `0.25`，會變成四倍慢動作。
聲音用兩層 `atempo=0.5` 一起放慢（atempo 單層下限是 0.5），
音高不變，聽起來像慢下來的轟鳴。

## 踩過的雷

- **手機直拍的檔案是 1920×1080 + 旋轉 -90 中繼資料**，ffprobe 報的寬高
  是旋轉前的。要看實際方向得查 `stream_side_data=rotation`。
- **drawtext 的 text 值裡冒號是參數分隔符**。沒跳脫的話
  「攝於 20:30–20:35」會只剩下 `35`，而且不會報錯。`esc()` 負責處理。
- 直式與橫式的中間檔要分開命名，否則同名互相覆蓋。
- **影像和聲音的轉場算式必須一致，否則會累積不同步。** 一開始每個鏡頭
  多渲染了 XFADE 秒「給轉場吃」，但 `xfade` 讓時間軸每段只前進
  `S-XFADE`，`acrossfade` 卻是每段前進 `S`，每接一次就錯開 XFADE 秒。
  11 個鏡頭累積下來聲音比畫面慢 4.95 秒（成品的影像軌 99.47s、
  音軌 104.02s 就是這個症狀）。正確做法是不要多渲染，讓 xfade 直接
  吃掉鏡頭尾端。檢查方式：`ffprobe` 看影像與聲音的 duration 是否相等。
- 片頭字卡一行塞不下「台南市南區灣裡黃金海岸 · 2026年11月7日（週六）」
  （1080 寬約放得下 20 個字），所以地點分短／長兩種寫法，片頭用短的
  分兩行排，片尾才用全名。
