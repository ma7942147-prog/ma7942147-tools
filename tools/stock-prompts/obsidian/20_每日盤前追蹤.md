# 📆 每日盤前追蹤（10 分鐘）

**目的**：不是看盤，是**檢查 S8 寫下的推翻條件有沒有被觸發**。
**大部分日子的正確答案是「沒事」。** 如果你每天都覺得有事要做，那多半是被新聞牽著走。

**什麼時候跑**：美股開盤前，或台灣時間早上。
**要準備什麼**：追蹤清單 + 每檔的 `invalidation_triggers`（從 `30_追蹤儀表板.md` 複製）。

---

## 📋 提示詞（複製這一段）

```text
你是我的投資追蹤助理。今天是 {{DATE}}。

【我的追蹤清單與推翻條件】
{{WATCHLIST}}
（格式：TICKER | 核心論點一句話 | T1 觸發條件 | T2 觸發條件 | T3 觸發條件）

【任務】做三件事，不要多做。

一、今日總體行事曆
列出今天與本週剩餘時間的重要經濟數據與事件（FOMC、CPI、PCE、非農、初領失業金、重要財報）。標明公布時間（台灣時間）與市場預期值。

二、追蹤清單觸發檢查
針對清單中每一檔，用過去 24 小時的公開資訊逐條檢查推翻條件，判定為：
- 觸發：條件已成立 → 寫出證據與來源
- 接近：距離門檻不到 20% → 寫出目前數值與門檻
- 正常：沒有跡象
只要有任何一檔是「觸發」或「接近」，就要寫出建議動作（去跑 S6 / S7 / S8 哪一步）。

三、昨日新聞掃描
掃描過去 24 小時與我的主線相關的新聞。針對每一則，只回答一個問題：
**這則新聞改變了什麼結構性的事，還是只是價格波動？**
只有被你判定為「改變了結構」的，才列進 news_to_deep_dive，並標註要用 S3 完整分析。
其餘一律不列。寧可漏，不要吵。

【輸出紀律】
1. 先給人類可讀的三段摘要，最後輸出一段 ```json 區塊，欄位與下方一致。
2. 每個判定都要附來源與時間。查不到就填 null，不准推測。
3. 如果三件事都沒有異常，就把 no_action_needed 設為 true，摘要控制在三行以內。
4. 不給買賣建議。

【JSON 格式】
```json
{
  "step": "DAILY",
  "date": "YYYY-MM-DD",
  "macro_calendar": [
    {"event": "", "time_tpe": "", "consensus": "", "prior": ""}
  ],
  "watchlist_alerts": [
    {"ticker": "", "trigger_id": "", "status": "觸發|接近|正常", "evidence": "", "current_value": "", "threshold": "", "next_step": "S6|S7|S8|無"}
  ],
  "news_to_deep_dive": [
    {"title": "", "source": "", "url": "", "what_changed": "", "related_trend": ""}
  ],
  "noise_ignored_count": 0,
  "no_action_needed": true,
  "notes": ""
}
```
```

## 🗂️ 每日紀錄怎麼存

用 `模板_每日盤前紀錄.md` 在 `每日筆記/` 建一則 `美股-YYYY-MM-DD.md`，把 JSON 貼進去。
frontmatter 的 `alerts` 與 `no_action_needed` 會被 `30_追蹤儀表板.md` 的 Dataview 抓去統計。

## 📌 紀律提醒

- **連續 5 天 `no_action_needed: true` 是健康的**，代表你的觸發條件寫得夠具體。
- 如果一週有 4 天以上出現 `news_to_deep_dive`，通常代表 S8 的觸發條件寫得太鬆，回去重寫。
- 「觸發」出現時，**先跑 S6 看有沒有新數據，再跑 S8 重新評估**，不要直接看股價做決定。
