# mv-render — 歌詞 MV 合成器

把「一首歌 + 圖片／影片 + 一份歌詞」合成一支 1080p 的歌詞 MV。

## 專案

素材與時間軸放在 `projects/<名稱>/`，引擎共用。所有指令都吃 `--project`
（或環境變數 `MV_PROJECT`），預設 `one_and_only`。

| 專案 | 內容 |
|---|---|
| `one_and_only` | 《The One and Only》4:32，19 張圖 + 1 段影片，49 個鏡頭 |
| `moon` | 《月娘圓》3:12，10 段直式影片，30 個鏡頭 |

```
projects/<名稱>/
  timeline.py      段落時間、歌詞時間碼、分鏡
  assets/          song.mp3 或 song.flac + 圖片／影片
  build/           產出（不進 repo）
  tap_times.json   手動打點結果（可選，存在時優先於偵測值）
```

```bash
MV_PROJECT=moon python3 render.py        # 或 python3 render.py --project moon
MV_PROJECT=moon python3 verify_sync.py
```

直式素材（例如 720×1280）放進 1920×1080 時，用「自己的放大模糊版填滿
兩側 + 原片等比置中」，不裁掉上下也不留黑邊。圖片和影片走同一套。

## 為什麼要自己算時間軸

Suno 產出的歌不會附時間碼。照歌詞平均分配的話，字幕一定會跟不上人聲。
所以這個工具直接分析音檔求時間。

### v1 的錯誤（已修正）

v1 用 novelty curve 猜出段落邊界，再把「整段長度」平均分給句子。
但歌手唱不滿整段——段尾都留給樂器。結果同一段裡每一句都比前一句
更晚，到段落最後一句可以晚 4~5 秒：

| | v1 排的位置 | 實際唱的位置 |
|---|---|---|
| Verse 1 唱到 | 56.30 | **50.91** |
| Pre-Chorus 1 進來 | 56.30 | **53.90** |
| Chorus 1 進來 | 77.00 | **74.77** |
| Chorus 2 進來 | 166.50 | **162.77** |

### v2 的做法

**人聲偵測**：v1 用 mid/side 抵消抓中置人聲，但這首的副歌是
wall of sound + 雙軌人聲、聲像整個外擴，中置人聲值反而趨近 0，
偵測直接失效。v2 改用：

1. 中值濾波 HPSS —— 時間軸中值取諧波、頻率軸中值取打擊，做出諧波遮罩
2. 取 300–4000 Hz 的對數能量，把它的**時間包絡帶通到 1.8–9 Hz**
   （人講話唱歌的音節速率）
3. 這個「調變能量」在有人唱時明顯高於純演奏段，而且不受聲像寬度影響
4. 遲滯門檻 (0.34 / 0.235) 取出實際演唱區間

驗證：純演奏段（189.5–206.8、253.5–267.5）調變能量 0.15–0.28，
演唱段 0.30–1.04，分得很開。

**句子定位**：分兩種情況處理

- Pre-Chorus / Chorus 句與句之間有換氣空隙 → **直接用量到的起唱點**
- 主歌 / Bridge 唱得太密量不到空隙 → 先依字數估位置，
  再在 ±25% 句長內找調變能量谷底（換氣點）微調。
  限制搜尋範圍是為了不讓個別句子被雜訊拉走

**提前量**：字幕提前 0.10s 出現、150ms 淡入，
實際看清楚的時間約等於起唱點（卡拉 OK 慣例，讓人來得及讀）。

### 怎麼驗證

```bash
python3 verify_sync.py
```

對每一句比對「字幕出現時間」與「實測起唱點」，
並檢查字幕出現後 1.3 秒內是否真的有人聲。目前結果：

```
字幕晚於起唱點超過 0.8s：1 / 45
字幕出現後 1.3s 內偵測不到人聲：0 / 45
```

唯一那句在連續演唱區間內，偵測器抓到的是前一句的起唱點，屬量測假象。

## 手動打點（最準的做法）

偵測器在編曲稀疏的地方很準，但後半段人聲被吉他牆蓋住時還是會抓不到。
這種時候直接用耳朵打點：

```bash
python3 make_tap_tool.py                       # build/tap.html，含「下載 tap_times.json」鈕
python3 make_tap_tool.py out.html --no-download # 給 Artifact 用（檢視器不給網頁下載檔案）
```

用瀏覽器打開 `build/tap.html`，按 <kbd>空白鍵</kbd> 在每一句起唱的瞬間打點：

| 鍵 | 動作 |
|---|---|
| <kbd>空白</kbd> | 打點，然後自動跳下一句 |
| <kbd>P</kbd> | 播放／暫停 |
| <kbd>←</kbd> <kbd>→</kbd> | 倒退／快轉 3 秒 |
| <kbd>↓</kbd> | 從這句的點往前 1.5 秒重聽 |
| <kbd>Backspace</kbd> | 退回上一句重打 |

- **可以只重打某幾段**：點段落標題就從那段開始，前面已經對好的點不會被動到。
- **補償滑桿**：人手按下去一定會慢 0.1~0.2 秒，預設自動往前挪 0.15 秒，
  調整時會即時套用到所有已打的點。（算完之後 `timeline.py` 還會再提前
  `LAG` 的 0.10 秒讓字幕早一點點浮出來，所以總共比打點時間早 0.25 秒。）
- 打點結果會自動存在瀏覽器裡，關掉再開不會不見。

打完按「下載 tap_times.json」（或按「複製全部」把 JSON 貼出來），
存成 `tools/mv-render/tap_times.json`，
`timeline.py` 就會**優先採用手打的時間**（人耳勝過偵測器），
沒打到的段落自動沿用偵測值。然後重跑：

```bash
python3 render.py
```

## 用法

```bash
# 需要 ffmpeg 與 CJK 字型
apt-get install -y ffmpeg fonts-noto-cjk

# 素材放進 assets/：song.mp3 + 圖片 + clip01.mp4
python3 render.py            # 完整輸出 build/MV_The_One_and_Only.mp4
python3 render.py --shots-only   # 只渲染分鏡，方便單獨檢查
python3 make_subs.py         # 只重產 build/lyrics.ass
python3 verify_sync.py       # 驗證每一句有沒有跟上人聲
```

## 檔案

| 檔案 | 內容 |
|---|---|
| `timeline.py` | 實測演唱區間、45 句歌詞時間碼、24 個分鏡（Ken Burns 參數） |
| `verify_sync.py` | 對時驗證：比對字幕出現時間與實測起唱點 |
| `make_tap_tool.py` / `tap_ui.html` | 手動打點工具（產生自帶音檔的單一 HTML） |
| `tap_times.json` | 手動打點結果，存在時優先於偵測值（不進 repo） |
| `make_subs.py` | 產生 ASS 字幕（歌詞 / 片頭字卡 / 片尾字卡） |
| `render.py` | 分鏡渲染 → xfade 串接 → 燒字幕 + 混音 |
| `assets/`, `build/` | 素材與產出，**不進 git**（個人內容） |

## 分鏡設計

49 個鏡頭，0.7s 交叉淡入淡出，切點對齊歌詞句子的起唱點：

- Intro 片頭字卡 + 台北夜景（1993 的城市）
- Verse 1 房間、公用電話、宿舍、書店 —— 舊時光的場景
- Pre-Chorus 1 咖啡店、套裝 —— 呼應「白上衣 窄裙 剛下班」
- Chorus 星空、海邊夕陽、城市夜景牽手影片
- Verse 2 書桌、鳥居、和服庭園、晴空塔 —— 現在的日子
- Pre-Chorus 2 / 間奏 婚禮四格漫畫逐格帶出（呼應「到白頭」）
- Bridge 回到特寫，編曲變薄、鏡頭收窄
- 尾奏 婚禮全頁由上而下慢移，最後回到第一個鏡頭收尾

素材 20 個（19 張圖 + 1 段影片），每張以不同裁切／推軌方向重複使用，
所以同一張圖在不同鏡頭裡看起來是不同的鏡位。

直式圖片用「模糊背景填滿 + 原圖等比置中」處理，不會有黑邊。
推軌先在 2x 解析度（3840×2160）算完再縮回 1080p，避免 zoompan 的抖動。
串接分批做（每 10 個鏡頭先接成一段再合併）—— 一次餵 49 個輸入給
ffmpeg 的 xfade chain 太重。
