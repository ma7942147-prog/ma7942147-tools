# mv-render — 歌詞 MV 合成器

把「一首歌 + 幾張圖 / 短影片 + 一份歌詞」合成一支 1080p 的歌詞 MV。
第一支作品：**《The One and Only》**（1993 中壢、野狼、中山北路）。

## 為什麼要自己算時間軸

Suno 產出的歌不會附時間碼。照歌詞平均分配的話，字幕一定會跟不上人聲。
所以這個工具直接分析音檔求時間。

### v1 的錯誤（已修正）

v1 用 novelty curve 猜出段落邊界，再把「整段長度」平均分給句子。
但歌手唱不滿整段——段尾都留給樂器。結果同一段裡每一句都比前一句
更晚，到段落最後一句可以晚 4~5 秒：

| | v1 排的位置 | 實際唱的位置 |
|---|---|---|
| Verse 1 唱到 | 56.30 | **50.91** |
| Pre-Chorus 1 進來 | 56.30 | **53.90** |
| Chorus 1 進來 | 77.00 | **74.77** |
| Chorus 2 進來 | 166.50 | **162.77** |

### v2 的做法

**人聲偵測**：v1 用 mid/side 抵消抓中置人聲，但這首的副歌是
wall of sound + 雙軌人聲、聲像整個外擴，中置人聲值反而趨近 0，
偵測直接失效。v2 改用：

1. 中值濾波 HPSS —— 時間軸中值取諧波、頻率軸中值取打擊，做出諧波遮罩
2. 取 300–4000 Hz 的對數能量，把它的**時間包絡帶通到 1.8–9 Hz**
   （人講話唱歌的音節速率）
3. 這個「調變能量」在有人唱時明顯高於純演奏段，而且不受聲像寬度影響
4. 遲滯門檻 (0.34 / 0.235) 取出實際演唱區間

驗證：純演奏段（189.5–206.8、253.5–267.5）調變能量 0.15–0.28，
演唱段 0.30–1.04，分得很開。

**句子定位**：分兩種情況處理

- Pre-Chorus / Chorus 句與句之間有換氣空隙 → **直接用量到的起唱點**
- 主歌 / Bridge 唱得太密量不到空隙 → 先依字數估位置，
  再在 ±25% 句長內找調變能量谷底（換氣點）微調。
  限制搜尋範圍是為了不讓個別句子被雜訊拉走

**提前量**：字幕提前 0.10s 出現、150ms 淡入，
實際看清楚的時間約等於起唱點（卡拉 OK 慣例，讓人來得及讀）。

### 怎麼驗證

```bash
python3 verify_sync.py
```

對每一句比對「字幕出現時間」與「實測起唱點」，
並檢查字幕出現後 1.3 秒內是否真的有人聲。目前結果：

```
字幕晚於起唱點超過 0.8s：1 / 45
字幕出現後 1.3s 內偵測不到人聲：0 / 45
```

唯一那句在連續演唱區間內，偵測器抓到的是前一句的起唱點，屬量測假象。

## 用法

```bash
# 需要 ffmpeg 與 CJK 字型
apt-get install -y ffmpeg fonts-noto-cjk

# 素材放進 assets/：song.mp3 + 圖片 + clip01.mp4
python3 render.py            # 完整輸出 build/MV_The_One_and_Only.mp4
python3 render.py --shots-only   # 只渲染分鏡，方便單獨檢查
python3 make_subs.py         # 只重產 build/lyrics.ass
python3 verify_sync.py       # 驗證每一句有沒有跟上人聲
```

## 檔案

| 檔案 | 內容 |
|---|---|
| `timeline.py` | 實測演唱區間、45 句歌詞時間碼、24 個分鏡（Ken Burns 參數） |
| `verify_sync.py` | 對時驗證：比對字幕出現時間與實測起唱點 |
| `make_subs.py` | 產生 ASS 字幕（歌詞 / 片頭字卡 / 片尾字卡） |
| `render.py` | 分鏡渲染 → xfade 串接 → 燒字幕 + 混音 |
| `assets/`, `build/` | 素材與產出，**不進 git**（個人內容） |

## 分鏡設計

24 個鏡頭，0.7s 交叉淡入淡出，轉場起點對齊段落邊界：

- Intro（0–16.3s）片頭字卡 + 書桌鏡頭慢推
- Verse 1 / 2 房間、電話、特寫，慢速推軌
- Pre-Chorus → Chorus 星空、城市夜景、雪中牽手影片
- Pre-Chorus 2 / 間奏 婚禮四格漫畫逐格帶出（呼應「到白頭」）
- Bridge 回到特寫，編曲變薄、鏡頭收窄
- 尾奏 婚禮全頁由上而下慢移，最後回到第一個鏡頭收尾

直式圖片用「模糊背景填滿 + 原圖等比置中」處理，不會有黑邊。
推軌先在 2x 解析度（3840×2160）算完再縮回 1080p，避免 zoompan 的抖動。
