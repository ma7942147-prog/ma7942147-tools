# travel-reel — 照片＋影片 → IG 直式遊記短片

把一整晚拍的照片和影片，挑出能看的、剪成一支 9:16 短片。
第一支：**《灣裡的一個晚上》**（2026-11-07 台南灣裡，39 秒）。

## 選片：先量、再看

技術面先用程式篩一輪（`qc.py`）：

- **清晰度**：取畫面中央 60% 算 Laplacian 變異。只看中央是因為夜拍
  背景本來就糊，邊緣糊不代表失焦，主體糊才是。
- **曝光**：平均亮度、對比、過曝比例、死黑比例。

這批 30 張全部通過（中央銳利度中位數 1739，最低的 211810 也有 963），
所以**真正的篩選是看內容**——程式只能排除「拍壞的」，排不掉「無聊的」。

逐張看完淘汰 8 張：主體太遠、夜裡大片黑、構圖雜亂的廣角空景。
留下的 22 張幾乎都是直幅，剛好對上 9:16。

## 節奏

- 煙火開場 7 秒（有現場原音），接花燈定場，再進 21 張花燈
- 每張 1.45–1.95 秒，重點的幾張給到 1.9 秒以上
- 0.35 秒交叉淡入，Ken Burns 推軌方向逐張交替，不會整支像同一個運鏡
- 字幕只有四句，片尾一張字卡

## 用法

```bash
python3 qc.py <照片夾>                    # 先看技術面有沒有該淘汰的
python3 render.py --photos <照片夾> --video <影片夾> --out <輸出夾>
```

剪輯表在 `reel.py`：照片清單、每張秒數、推軌參數、字幕時間。

## 踩過的雷

- **一次把 25 個 1080×1920 的輸入餵進同一條 xfade/acrossfade 鏈，
  ffmpeg 會被 OOM killer 幹掉**，而且產出 0 byte、stderr 什麼都不留，
  看起來像「沒聲沒息地結束」。改成每 6 段先接成一塊再合併。
- **影像和聲音的轉場算式必須一致。** 每段都不要多渲染轉場的長度，
  讓 xfade 直接吃掉尾端；多渲染的話聲音每段會多前進一個轉場長度，
  累積成不同步。檢查方式：`ffprobe` 比對兩軌 duration。
- 照片段沒有音軌，`acrossfade` 會失敗，要先補等長的 `anullsrc`。
- `drawtext` 的 text 值裡冒號是參數分隔符，沒跳脫會被吃掉且不報錯。
